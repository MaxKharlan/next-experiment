# Analyze saved Kaggle results

Run from the repository root:

```bash
uv run python -m scripts.analyze_kaggle artifacts/kaggle/results.json \
  --min-effect 0.06 \
  --out artifacts/kaggle/analysis.json
```

Here `0.06` is an example decision threshold, not a Kaggle calibration. Choose the threshold before comparing the arms. Output files must not already exist. The command reads JSON and calculates statistics; it does not train, load models, call providers, or enter the API investigation queue.

Omit `--noise-sd` to estimate variance from the imported target and control measurements. Supply it only when there is an independent noise measurement for the same environment and evaluation protocol. No Token Factory noise estimate is applied automatically.

## Export format

`docs/kaggle-results.schema.json` describes the version-1 bundle. A bundle contains:

- `version`: `1`; `backend`: `kaggle`; `model`: the base model ID; `fault`: `answer_truncation`.
- `evaluation`: `split` (`check`, `validation`, or `test`), `sha256` of the evaluated JSONL bytes, `examples`, and `metric`: `exact_match`. Every run must use this same evaluation dataset and metric.
- `environment`: a string dictionary with package versions, GPU and notebook revision when available.
- `control_description`: the actual control intervention, required for a causal verdict.
- `runs`: measurements with unique `run_id`, `role`, integer `seed`, numeric `metric` in [0, 1], `train_sha256`, and `hyperparameters`. Roles are `healthy`, `damaged`, `target`, and `control`.

An optional `summary_path` on a run references an existing summary, relative to the bundle directory. The importer checks its model, seed, hyperparameters and `final.exact_match`, and records the file hash. A summary generated by the current `train_lora.py` scores validation. It cannot be relabeled as a check result. A separate evaluator can save an `evaluation` object in its summary; it must match the bundle's evaluation object. Do not add that object to a validation score to change its meaning.

Without summary files, the importer accepts the supplied measurements and labels them as exporter declarations. Dataset hashes identify the claimed inputs; the importer does not have the training data and cannot independently prove that these files were used. Save the original notebook output and evaluation records with the export.

## Interpretation

Healthy and damaged measurements produce mean scores and `quality_drop`, but no causal verdict. Missing arms or fewer than two seeds per arm produce `insufficient_evidence`.

Causal analysis requires target and control measured on a separate `check` set, matching seed sets, identical hyperparameters, different training-file hashes and a control description. Validation and test measurements remain descriptive. The importer does not verify whether the control matches the target in token count, class balance or training cost; these belong in the experiment protocol.

The verdict uses `core.interventions.stats.causal_check`, an unpaired rule despite matched seed labels. Its permutation test cannot reach 0.05 with two seeds per arm; the existing rule then decides from the interval. The report exposes this limitation through `permutation_can_reach_0_05`. Estimates from very few seeds remain uncertain. At most eight seeds per arm are accepted because the current permutation implementation enumerates combinations in memory.

The report preserves the measurements, input hash, optional summary hashes, threshold, variance source, effect, confidence interval and decision rule. A confirmed comparison supports the specified intervention against its control; it does not by itself establish complete recovery to the healthy model.
